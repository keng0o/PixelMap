# 真上視点の彩色ゲーム地図：風景構成とアセット設計

- 日付：2026-09-05 JST
- 状態：2026-09-05 JST、方針および本文の実装承認済み。
- 参考：ユーザー提供の赤茶の屋根、淡い黄緑の地面、灰青の川、重なる樹冠を持つ736×952pxの地図。
- 目的：実際の街の位置関係を土台に、屋根・樹冠・小径・水辺を同じ画風と縮尺で組み立て、歩いて探索したくなる真上視点の地図を作る。
- 文書作成時点では描画・操作・アセットを変更せず、本文承認後に実装へ進む。

## 1. 承認された方針

地理データの取得、座標変換、現在地、ドラッグ操作を活かし、地理を風景として構成する層と、その出力を描くアセット体系を設計する。輪郭と大きな色面を先に成立させ、細部を段階的に足す。

まず小さな完成風景を作り、そこで決めた線・色・縮尺・余白の規則を実地図へ適用する。単体アセットの原寸再現だけを完成基準にしない。

## 2. 調査時点と対象範囲

手元の作業ツリーは `de7da8e`、調査時の `origin/main` は `632df37`。手元の真上視点はv11、公開中はv12のsemantic miniatureであり、作業ツリー全体をそのまま公開してはいけない。実装は開始時点の `origin/main` を土台にし、既存の公開済み変更を維持する。

通常の変更範囲はstandalone testである。入口は `variants/map-02-refined.html?profile=illustrated-landscape&presentation=art` とし、standaloneのときだけ専用の `variants/map-12-illustrated-landscape.html` へ接続する。embedded表示ではこの分岐を無効にする。

既存の `topdown-game`、通常のstandalone、本番の `index.html`・`compare.html`・`four-maps.html`・`variants/height-stack-four-map.html`、`mobile/` は対象外。既存の素材比較ラボも変更しない。新しい描画を本番へ反映するには `全てに反映` の指示を必要とする。

## 3. 地図として維持するもの

- 道路・鉄道・水系の位置と接続、橋とトンネルの区別を維持する。見た目のために道路を間引いたり、架空の近道を作ったりしない。
- 建物の位置、外形の主要な特徴、独立した棟、中庭の穴を保つ。小建物は細部を省略しても、表示用の集落へ置き換えない。
- 森・公園・草地・畑などは取得できる土地情報に基づく。未知の土地は穏やかな中立の地表として描く。
- 植生の描画variationは、実在する個別樹木の位置や種類を保証する情報として扱わない。植生表現は根拠のある領域内へ制限する。
- 地理情報にない川、畑、建物、施設入口、歩行可能な通路を創作しない。屋根素材や棟線は視覚上の解釈として扱う。
- 地形形状の単純化や装飾線の揺れは、地物同士の接続や隣接関係を変えない範囲に限る。

密集市街地を農村へ変換しない。市街地では街区・屋根群・公園・川沿いの開けた空間で密度差を表す。

## 4. 画風の基準

### 視点と縮尺

北上固定の真上視点とし、建物は屋根面と短い接地影で表す。壁面の押し出しは使わない。既存の原子セル建物に関するADR-0003は変更せず、独立testとして扱う。

736×952pxの基準画面と390×844pxのスマートフォン画面で評価する。小屋の棟線を読ませることだけを理由に全建物を拡大せず、表示範囲と細部の省略を調整する。低解像度Canvasの整数拡大は前提にせず、細い輪郭を読める描画解像度を保つ。

### 色と線

- 地表：淡い黄緑・生成り。広い面として低コントラストにする。
- 建物：赤茶・テラコッタを中心に、屋根の明面と暗面を少数色で分ける。
- 水面：灰青。水系を追える明度差を確保する。
- 植生：落ち着いた緑。近隣の木では色調を揃え、森と草地を密度でも分ける。
- 輪郭：濃い茶または緑を含む暗色。外形、棟線、表面模様の順に強さを下げる。
- 影：短く、方向を統一する。アセットを回しても光の方向は画面内で揃える。

初期の完成風景は不透明の大きな色面と輪郭を基本にする。全面ノイズ、ぼかし、紙汚れを画風の必須条件にしない。草の短線や岸辺の細線は独立した細部層にし、表示サイズに応じて抑制する。

## 5. アセット体系

完成した一軒の絵を任意の建物へ引き伸ばす方式を避け、構造を組み合わせられる部品を用意する。

| 群 | 初期の構成 | 適用規則 |
| --- | --- | --- |
| 屋根 | 切妻・寄棟・長屋・平屋根・L字・中庭型、付属棟、棟線、影 | 元の形と縦横比に合わせて構造を選ぶ。複雑な外形では屋根面を分け、中庭を塗り潰さない |
| 樹木 | 大小の単木、不整形の樹冠、重なる樹冠、低木 | 輪郭と大きさにvariationを持たせ、付近の色と線を揃える |
| 森 | 林内の地色、樹冠群、林縁、下草 | 内側は密にし、外側では森の輪郭と個々の木を読ませる |
| 道 | 路面、道端、交差点、橋の接続、路面の疎な模様 | 地理の線形に沿って連続させる。交差点や橋で模様や輪郭が途切れない |
| 水辺 | 水面、岸、流れの線 | 岸との距離と流れの方向に応じて配置する |
| 地面 | 中立地表、草地、裸地、舗装、畑の模様 | 土地情報に応じて選ぶ。畑の列など方向性のある模様は領域ごとに揃える |

既存の `illustrated-reference-materials.js` の赤い屋根と樹冠は、形・色の基準として使う。既存ラボのカタログを直接書き換えず、新しいアセット群に必要な構造を移す。参考画像そのものはリポジトリや公開サイトへ追加しない。

## 6. 風景を構成する処理

処理は「正規化された地理 → 周辺関係の整理 → 配置と屋根構造 → 描画」の順とする。

1. **地理の受け取り**：既存の取得・デコード・座標変換を再利用する。新しい画風のために既存の公開用runtimeへ動作変更を混ぜない。
2. **周辺関係の整理**：道路・水辺・建物・植生領域の近接関係と重なりを調べる。道端、水際、林縁、街区内の地表に描画上の役割を持たせる。
3. **配置と構造**：建物の屋根面を構成し、植生領域へ樹冠群を配置する。道路・鉄道・水面・屋根との衝突判定には、樹冠中心だけでなく描画される輪郭の広がりを使う。
4. **描画**：地表、水辺、道、植生、屋根などの順序とマスクを統一し、線・色面・細部を合成する。橋は水面の上、通路は通路として読み取れる状態にする。

森の内部では重なった木の境界線を弱め、林縁を強くする。道路脇や水際の細部は領域の境界に沿わせる。空いている場所へ一律に装飾を散布しない。

variationの種は地理上の安定したIDまたは座標から決める。画面座標や表示順に依存させない。パン前後、再描画、隣接タイルで同じ範囲の樹木や屋根が入れ替わらないようにする。タイル境界をまたぐ地物は同一地物として扱い、装飾の重複や切断を防ぐ。

## 7. UI、操作、失敗時の表示

全画面の地図、現在地ボタン、地図データ帰属、一時的な状態表示を基本とする。ドラッグ移動と現在地への移動を維持する。今回の画風を成立させるための架空の旅人・目的地・主経路は追加しない。

タイル取得失敗は再試行可能にし、直前の描画を維持する。位置情報の拒否・タイムアウトで地図を失わず、操作ボタンを復帰させる。データが足りない領域では、架空の景物で補わず中立の地表と取得状態を表示する。

## 8. 実装順と検証

### 第一段階：完成風景

数軒の家、道の分岐、植生、水辺を含む小さなfixtureを、test用の基準風景として作る。人工fixtureの場合は実地図と明確に区別する。同じ描画処理を本番の実地理表示でも使える形にし、fixture専用の見た目で合格しない。

色面だけでも道・屋根・森・水面を識別できること、木と家の縮尺が揃うこと、道端の余白と林縁が読めることを確認する。

### 第二段階：実地図へ接続

川崎駅周辺、河川沿い、緑地を含む郊外の3種類で評価する。各地点の座標と表示範囲を検証記録に保存し、再現可能にする。都市と郊外で画風を揃えつつ、実際の密度差を残す。

### 自動検証

- 複数棟と中庭を含む建物、斜めの道、交差点、橋、タイル境界をまたぐ地物をfixtureで確認する。
- 通路・水面・屋根に植生が侵入しないこと、同じ地理範囲で配置が安定することを検証する。
- command生成だけでなく実際のpaint処理と診断値の整合を確認する。
- standaloneの明示profileだけで有効になり、既存test・本番・mobileに変更がないことを確認する。
- 該当テスト、全Nodeテスト、`node build.mjs`、差分検査を行う。

### 視覚検証と完了条件

736×952pxと390×844pxで完成風景と実地図を撮影し、元の参考画像とともに独立サブエージェントへ渡す。評価は、真上視点、色と線、縮尺、道の連続性、密度差、林縁、繰り返し、細部の潰れを対象とする。

問題または新しい回帰があれば修正・撮影・レビューを繰り返す。最新画像がPASSになるまで実装の公開と完了報告をしない。機能テストの成功だけを画風の完成と扱わない。

`log.html` にJST日付、`testのみ`、新しいprofile、production影響なし、検証内容を最新順で追記し、差分表を更新する。意図したファイルだけをcommitし、`origin/main` へpushする。GitHub Pagesの対象commitのbuild成功を待ち、公開された対象ページで描画、ドラッグ、diagnostics、console、最新画面を確認する。

第一段階だけを地図全体の実装完了として報告しない。実地理への接続、視覚レビュー、公開確認までを今回の実装範囲とする。
