# 方向別石造橋スプライトセット設計

- 日付: 2026-09-02
- 対象: 地図配置前の橋単体ピクセル素材
- 状態: 文書承認済み、実装前

## 目的

参照画像にある、幅広い路面、厚い欄干、石造の橋台、2つの大きなアーチを備えた灰色の石橋を、PixelMapの投影規則と矛盾しない12方向のピクセル素材として作る。

12枚を個別に描くのではなく、1つの共通形状から決定論的に生成する。方向が変わっても橋の長さ、幅、高さ、アーチ比率、接地点、照明が揺れず、同じ橋を回したものとして見えることを最優先する。

## 成功条件

次の条件をすべて満たしたとき、方向別素材の作成を完了とする。

1. 0度から165度まで15度刻みの12方向がそろっている。
2. 全方向で同一の橋の形状、寸法、色、接地点を使っている。
3. 地面上の橋軸だけが回転し、高さは常に画面上、橋体の奥行きは常に画面下へ伸びる。
4. 垂直線が傾かず、光源が全方向で画面左上に固定されている。
5. 背景は透明で、半透明画素とアンチエイリアスを含まない。
6. 一覧シートで12方向を比較し、同じ立体感と同じ橋として読める。
7. 地図ページ、共有レンダラー、本番ページを変更しない。

## スコープ

### 対象

- 方向別橋スプライトを生成する決定論的ジェネレーター
- 12枚の透過PNG
- 12方向を一度に比較する検査用スプライトシート
- 角度、中心、接地点、画像範囲を記録するmanifest
- 自動検証と独立した目視レビュー

### 対象外

- 地図への配置、道路や河川との合成、橋データの識別
- 小・中・大のサイズ違い
- 橋の長さやアーチ数が異なる別モデル
- `variants/map-02-refined.html`を含む地図ページの変更
- 1・2・4マップ本番ページへの反映
- GitHub Pagesへの公開

## 投影の前提

現在のcell2/cell3レンダラーは、建物や構造物を固定消失点へ向けて押し出していない。地面形状はbearingに応じて回転する一方、高さは接地点から画面上へ垂直に伸びる。

橋素材もこの規則に合わせる。

```text
地面上の橋軸・橋幅  bearingに合わせて回転
欄干の高さ          常に画面上
橋体の厚み・落差    常に画面下
垂直辺              常に画面垂直
光源                常に画面左上
```

このため、ここでいう「同じ消失点」は、12枚に個別の透視図法を与えることではない。共通の地面回転と画面垂直押し出しを守り、すべての方向で同じ投影体系に見せることを意味する。

橋軸が画面垂直に近い方向では、長辺側のアーチ面が正面方向から外れて細く見える。方向ごとにアーチを広げる補正は行わず、共通形状を投影した結果を採用する。

## 採用方式

### 共通モデルからの決定論的生成

橋を論理ピクセル座標上の部品に分け、同じ幾何モデルを12方向へ回転・ラスタライズする。

- 路面
- 左右の欄干
- 石造側壁
- 2つの半円アーチ開口
- 両端の橋台
- 輪郭、ハイライト、構造影、石目

この方式なら、角度ごとの拡大率、橋幅、欄干高、アーチ位置のずれを構造的に防げる。生成結果は同じ入力から常に同じ画素列になる。

### 採用しない方式

12方向を画像生成で個別に作る方式は採用しない。各画像の形状、アーチ数、材質、照明、縮尺が独立に変化し、同じ橋であることを保証できないためである。

斜め向きの完成PNGを機械的に回転する方式も採用しない。欄干の垂直線、橋体の画面下方向への厚み、固定光源まで回転し、現在の地図投影と矛盾するためである。

既存の`assets/bridge-study/bridge-reference-pixel-art-v1.png`は、橋の印象、石材色、アーチ構成を確認する視覚参照としてだけ使う。回転元画像または幾何入力にはしない。

## 共通幾何契約

すべての方向で次の値を共有する。

| 項目 | 値 |
| --- | ---: |
| 論理キャンバス | 96×96 px |
| デッキ中心兼接地点 | x=48, y=40 |
| 橋の全長 | 52 px |
| 石造部の全幅 | 22 px |
| 車道幅 | 14 px |
| 欄干厚 | 3 px |
| 欄干高 | 4 px、画面上方向 |
| 側壁深さ | 9 px、画面下方向 |
| アーチ数 | 2 |
| アーチ開口 | 14 px幅、7 px高 |
| 橋台長 | 両端各6 px |

局所座標は、`u`を橋軸方向、`v`を橋幅方向とする。画面座標は右を`+x`、下を`+y`、角度は画面上で時計回りとする。

```text
x = 48 + round(u cos(theta) - v sin(theta))
y = 40 + round(u sin(theta) + v cos(theta))
```

地面形状はこの変換で回転する。欄干の上端は変換後の画素から`[0, -4]`、側壁の下端は`[0, +9]`へ画面垂直に押し出す。

可視側壁は、回転後のデッキ外周のうち画面下向きのシルエット境界から作る。アーチは橋軸方向の共通位置に置き、その可視側壁から開口としてくり抜く。方向別の手修正は行わない。

ポリゴンはアンチエイリアスなしの整数走査変換で塗り、細線はsupercover規則で接続を保つ。座標丸めと描画順は固定し、同じ環境で生成し直したときにPNGの内容が一致するようにする。

## 方向契約

生成対象は次の12方向とする。

```text
000  015  030  045  060  075
090  105  120  135  150  165
```

`000`は橋軸が画面左右へ水平に伸びる方向である。橋は軸方向と幅方向の両方で対称なので、180度から345度は同じ形状の重複となり、個別ファイルを作らない。後の地図統合では角度を180度で正規化し、最寄りの15度素材を選択できる。

## 色と照明

背景以外の画素は次の固定パレットだけを使う。

| 用途 | 色 |
| --- | --- |
| 最外輪郭 | `#2b292e` |
| 路面 | `#7a7478` |
| 路面ハイライト | `#999295` |
| 石材明部 | `#d8d0c0` |
| 石材中間 | `#aaa397` |
| 石材暗部 | `#6b6459` |
| アーチ内・深い影 | `#303b46` |
| 背景 | alpha 0 |

光源は画面左上に固定する。上面は明るく、画面下へ落ちる側壁は中間色、右下を向く継ぎ目とアーチ内部は暗くする。石目は共通の局所座標パターンから生成するが、明暗の選択は固定光源を基準に行う。

影や石目を理由に方向ごとの色を追加しない。全画素のalphaは0または255だけとする。

## 描画順

奥行き関係が方向によって反転しないよう、画面上の位置から描画順を決める。

1. 画面下側の石造側壁と橋台
2. アーチ内部の暗部
3. デッキ上面
4. 奥側欄干
5. 近側欄干
6. 最外輪郭
7. 路面ハイライトと最小限の石目

同じ深度では画面y、画面x、部品の固定IDの順で安定ソートする。方向別の例外順序は持たない。


manifestは次を保持する。

- 形式バージョン
- キャンバス寸法
- デッキ中心と地図配置用接地点
- 共通幾何寸法
- 投影方式`screen-vertical`
- 固定光源`screen-top-left`
- 各素材の角度、ファイル名、不透明画素範囲

一覧シートは6列×2行とし、各セルに角度ラベル、96×96の原寸素材、4倍nearest-neighbor拡大を並べる。原寸と拡大の両方を同じファイルで確認できる構成にする。

## 検証

### 自動検証

ジェネレーター実行時に次を検証し、1件でも失敗したら既存成果物を置き換えない。

- 角度集合が12件で重複なく、15度刻みの指定値と完全一致する。
- 全画像が96×96のRGBA PNGである。
- alpha値が0または255だけである。
- 不透明画素が固定パレット以外を含まない。
- 中心、接地点、共通幾何寸法が全方向で一致する。
- 不透明画素がキャンバス外へ切れていない。
- 各画像に路面、欄干、輪郭の用途色が存在する。側壁とアーチ影は、投影後の可視面積が1px以上の方向だけ存在を要求する。
- 同じ入力で2回生成したPNGとmanifestの内容ハッシュが一致する。
- 地図ページと共有レンダラーに差分がない。

未知の角度、重複角度、非整数寸法、未定義色、半透明画素を検出した場合は生成を中止する。全画像を作業用出力へ生成して検証し、全件合格後だけ成果物をまとめて更新する。

### 目視検証

一覧シートで12方向を比較し、次を確認する。

- 全方向が同じ橋、同じ縮尺、同じ石材に見える。
- 0度、45度、90度で垂直線が画面垂直を保つ。
- 橋体の厚みが画面下、欄干の高さが画面上へ出ている。
- 光が画面左上から当たり、方向と一緒に回転していない。
- アーチの定義位置、大きさ、橋台寸法が方向ごとに変化せず、見える量の差だけが投影から生じている。
- 参照画像の「幅広い灰色路面、厚い欄干、大きな石造アーチ」という特徴が残っている。
- 90度付近のアーチ面が細くなる場合も、橋全体の立体構造が破綻していない。

最新の一覧シートと参照画像を独立レビューへ渡す。形状の同一性、投影、照明、ピクセル境界のいずれかに問題があれば共通モデルを修正し、全12方向を再生成して再レビューする。方向別の局所修正では解決しない。

## 完了境界

この段階の完了物は、方向別素材、一覧シート、manifest、ジェネレーター、検証結果である。地図上での選択、拡縮、道路との位置合わせ、河川マスク、橋種別の判定は次段階の別設計とする。

方向別素材が完成しても、standalone testページまたは本番ページへ自動的には反映しない。地図統合は素材の目視承認後にだけ開始する。
