# 部品合成式石造橋レンダラー設計

- 日付: 2026-09-02
- 対象: 地図配置前の石造橋単体レンダラー
- 状態: チャット設計承認済み、文書レビュー待ち
- 前設計: `2026-09-02-directional-bridge-sprite-set-design.md`

## 背景

現在の橋素材は、共通モデルから15度刻みの12方向を生成している。ただし実行時に利用できる成果物は方向別の完成PNGであり、橋の長さや幅を変えるには別画像の追加または画像全体の拡大縮小が必要になる。

今回の設計では、橋台、床版、路面、側壁、アーチ、橋脚、欄干、石積みを再利用可能な描画部品へ分解する。完成PNGを実行時アセットとして選ぶのではなく、1つのモデルから必要な角度と寸法の橋を論理ピクセル単位で合成する。

方向別画像を廃止すること自体が目的ではない。参照画像の太い石造感を保ちつつ、角度、長さ、幅が変わっても同じ橋、同じ投影、同じ照明として読めることが目的である。

## 目的

1. 0度から175度まで5度刻みの36方向を、1つの共通モデルから描画する。
2. 橋の長さ、石造部の全幅、路面幅を独立して変更できるようにする。
3. 固定端部と反復可能な中央部を組み合わせ、完成画像の引き伸ばしを行わない。
4. 全方向で高さを画面上、側壁の深さを画面下へ固定し、PixelMapの画面垂直押し出しと一致させる。
5. 参照画像の幅広い灰色路面、厚い石造欄干、暗いアーチ開口、橋脚、石積み細部を維持する。
6. 部品エンジンを地図から分離し、まず橋単体の研究ページで検証する。

## 対象外

- 今回の部品レンダラーをMVT由来の橋へ配置すること
- `variants/map-02-refined.html`または本番ページの橋描画を変更すること
- 道路、河川、鉄道との位置合わせを完成させること
- 石造アーチ橋以外の鉄橋、吊橋、歩道橋を同時に一般化すること
- 任意の連続角度をサブピクセル補間すること
- 遠近法による固定消失点または透視投影を新しく導入すること
- 方向別の完成PNGを実行時に読み込むこと

地図接続は、単体レンダラーの視覚承認後に別設計として行う。

## 採用方式

### 論理部品の手続き描画

橋をビットマップ部品ではなく、局所座標上の幾何部品と描画規則として定義する。

- 端部は固定形状として再利用する。
- 中央部は径間、橋脚、欄干区間、石積み模様を反復する。
- 幅変更は路面、余白、欄干の位置を再計算して行う。
- 角度変更は地面形状だけを回転し、高さと壁深さは画面垂直に保つ。
- 部品を個別の完成画像として重ねず、マスクを合成してから輪郭を引く。

この方式を採用する理由は、5度刻みと可変サイズを同時に満たしながら、ピクセル境界、照明、垂直線を一貫させられるためである。

### 採用しない方式

小さなPNG部品を回転して連結する方式は採用しない。5度回転でピクセル境界が不安定になり、欄干の垂直線、側壁の画面下方向、固定光源まで回転してしまうためである。

36方向と複数サイズを事前生成するアトラス方式も採用しない。実行時は軽いが、方向数とサイズ数の積だけ成果物が増え、連続的な長さと幅に対応できないためである。

## 全体構造

システムを次の3層へ分ける。

### 1. BridgeModel

地図から独立した橋の正規化モデルである。

```js
{
  id,
  screenAngle,
  length,
  masonryWidth,
  roadWidth,
  wallDepth,
  parapetHeight,
  styleKey: "stoneArchReference",
  detailLevel: "auto",
  patternSeed
}
```

単位はすべて論理ピクセルとする。`screenAngle`は画面上で時計回りの角度であり、地図方位ではない。将来の地図アダプターが橋軸とbearingから`screenAngle`を求める。

### 2. BridgeComponentCore

局所座標の部品、サイズ検証、径間配置、投影、面マスク、描画命令、診断値を生成する純粋エンジンである。DOM、Canvasコンテキスト、MVT、緯度経度には依存しない。

ブラウザとNodeの比較シート生成が同じ実装を使えるよう、既存のビルド工程を必要としないデュアル環境の共有モジュールとする。ブラウザではグローバルAPI、Nodeでは同じAPIをモジュールとして取得する。形状計算をブラウザ用と生成ツール用に二重実装しない。

### 3. BridgeRenderer

描画命令を配置先へ渡す薄いアダプターである。単体研究ページでは参照路面を含む全層を描く。将来の地図アダプターでは、エンジンが返す路面マスクの内側へ既存の道路スキンを描く。

初期実装のファイル境界は次とする。

- `assets/bridge-component-core.js`: `BridgeModel`、部品構成、投影、描画命令、キャッシュ
- `assets/bridge-component-preview.js`: 研究ページ専用のCanvas描画と操作欄
- `tools/generate-bridge-component-sheet.mjs`: 共有コアを使う1枚の比較シート生成
- `tests/bridge-component-*.test.mjs`: コア、ラスタ結果、キャッシュ、比較シートの契約

既存の`assets/bridge-renderer.js`は地図研究モード用なので、今回の単体実装では変更しない。地図接続段階で、新しい共有コアを消費するアダプターへ置き換えるかを別途設計する。

## 座標と角度

局所座標は次の3軸を使う。

- `u`: 橋の長さ方向
- `v`: 橋の幅方向
- `z`: 地面から上方向の高さ

角度は180度で正規化する。

```text
normalized = ((angle % 180) + 180) % 180
quantized  = (floor((normalized + 2.5) / 5) * 5) % 180
```

2.5度のちょうど中間は時計回り側の5度へ送る。橋は軸の両方向で対称なので、180度から355度は0度から175度と同じ構造を使う。

地面座標は次で投影する。

```text
x       = anchor.x + round(u cos(theta) - v sin(theta))
yGround = anchor.y + round(u sin(theta) + v cos(theta))
yTop    = yGround - z
yWall   = yGround + wallDepth
```

共有頂点は一度だけ投影して部品間で共有する。斜線はsupercover規則でラスタライズし、5度方向でも1ピクセルの穴を作らない。半透明画素とアンチエイリアスは使わない。

## 部品契約

| 部品 | 役割 | 可変サイズ規則 |
| --- | --- | --- |
| 橋台 | 両岸へ接続する端部 | スタイルで定めた長さを左右に1個ずつ置く |
| 床版 | 橋全体の上面 | `length × masonryWidth`から生成する |
| 路面 | 通行面 | `roadWidth`で中央へ配置する |
| 側壁 | 橋体の立体面 | 可視外周から画面下へ`wallDepth`だけ生成する |
| アーチ | 側壁の開口 | 有効長から個数と径間幅を算出する |
| 橋脚 | アーチ間の支柱 | 径間境界に固定基準幅で置く |
| 欄干 | 路面両側の低い壁 | 固定厚、固定高で長さ方向へ連続させる |
| 石積み | 壁、橋台、迫石、笠石の細部 | 各面マスク内に決定論的に配置する |
| 影 | 接地と奥行き | 合成済みの構造マスクから生成する |

初期スタイルは`stoneArchReference`だけとする。他の橋種別は同じ公開契約を使えるが、今回の実装には含めない。

初期スタイルの基準値は、承認済みの96×96参照橋を保つため次に固定する。

| 項目 | 値 |
| --- | ---: |
| 左右の橋台長 | 各6 px |
| 基準径間長 | 20 px |
| 最小径間長 | 10 px |
| 基準橋脚幅 | 4 px |
| 欄干厚 | 左右各3 px |
| 欄干高 | 4 px |
| 側壁深さ | 9 px |

## 長さと径間の計算

スタイルは次の基準値を持つ。

- 左右の橋台長
- 基準径間長
- 最小径間長
- 基準橋脚幅

有効長は次で求める。

```text
usableLength = length - 2 * abutmentLength
```

最初のアーチ数候補は、基準径間長と基準橋脚幅へ最も近くなる整数とする。

```text
archCount = max(
  1,
  round((usableLength + pierWidth) / (preferredSpanLength + pierWidth))
)
```

候補の径間幅が`minimumSpanLength`未満なら、条件を満たすまでアーチ数を1ずつ減らす。各径間と橋脚は橋中心を基準に左右対称へ配置する。整数除算の余りは、外側の対応する要素を同じ幅に保ち、中央要素へ吸収させる。アーチ数が偶数なら中央橋脚、奇数なら中央径間が奇数ピクセルを受け持つ。この規則により、左右端のどちらかだけが長くならない。

短い橋は1連、標準橋は2連、長い橋は3連以上になる。アーチの輪郭は各径間の実幅から生成し、完成アーチ画像を横方向へ拡大しない。

## 幅の計算

幅は次の関係を必須とする。

```text
masonryWidth
= leftParapetThickness
+ leftShoulderWidth
+ roadWidth
+ rightShoulderWidth
+ rightParapetThickness
```

左右の欄干厚と余白は同じ値にする。入力された`masonryWidth`と`roadWidth`から左右余白を算出し、奇数の余りは橋中心線の画素へ吸収させる。路面を片側へずらさない。

次の条件を満たせない入力は通常の石造アーチ橋として無効である。

```text
length >= 2 * abutmentLength + minimumSpanLength
masonryWidth >= roadWidth + 2 * parapetThickness
roadWidth > 0
```

## 可視面、押し出し、照明

地面上の床版外周から画面下側を向く辺を可視側壁として選ぶ。可視判定は投影後の辺と外向き法線から行い、角度別の例外表を持たない。橋軸が画面垂直に近い方向では長辺側のアーチ面が細くなり、90度では正面化しない。

高さは常に画面上、側壁の深さは常に画面下へ押し出す。すべての垂直辺は画面垂直を保つ。

光源は画面左上へ固定する。部品の局所的な左右ではなく、投影後の面の向きから明暗を選ぶ。橋を回転しても光源は回転しない。

## 細部と詳細度

参照画像に合わせ、次の細部を描き分ける。

- 水平の石積み段
- 交互にずらした垂直目地
- アーチ周囲の迫石
- アーチ頂部の要石
- 中央橋脚と橋台の縁石
- 欄干上部の笠石継ぎ目
- 欄干の支柱
- 路面の舗装継ぎ目

細部は必ず対応する面マスクで切り抜く。アーチ開口、路面外、透明領域へ目地を漏らさない。

`detailLevel: "auto"`では、部品が必要最小幅を下回る順に、舗装継ぎ目、欄干支柱、細かな垂直目地を省略する。床版、欄干の輪郭、アーチ開口、橋台、橋脚は意味を担う構造なので省略しない。同じモデルと`patternSeed`からは常に同じ模様を生成する。

## 出力契約と描画順

部品エンジンは次を返す。

```js
{
  underlay,
  surfaceMask,
  surface,
  overlay,
  bounds,
  stats,
  diagnostics
}
```

各描画命令は少なくとも`x`、`y`、`color`、`kind`、`componentId`、`layer`を持つ。配列は安定した順序で返し、同じ入力の比較がバイト単位で一致するようにする。

描画順は次の通りとする。

1. 構造影
2. 奥側の側壁、橋台、アーチ開口
3. 橋脚と手前側壁
4. 床版
5. 路面または既存道路スキン
6. 奥側欄干
7. 手前側欄干
8. 迫石、要石、笠石、石積みなどの細部
9. 合成後の外周輪郭

部品ごとの輪郭を先に重ねない。面マスクを結合してから最終輪郭を求め、部品境界に黒線や透明な隙間が出ることを防ぐ。

## 地図との将来の接続境界

単体研究ページは`surface`へ参照路面スキンを描く。将来の地図アダプターは次の順に合成する。

```text
underlay
→ 既存の道路描画をsurfaceMask内へ描く
→ overlay
```

地図アダプターだけがMVT記述子、橋軸、bearing、道路幅、画面位置を知る。部品エンジンは道路分類や地図レイヤー順を知らない。この分離により、橋の構造を変えずに道路側の色、太さ、模様を維持できる。

今回の実装ではこの地図アダプターを作らない。既存の地図上の橋描画は変更しない。

## キャッシュ

完成PNGではなく、原点中心の描画命令と面マスクをキャッシュする。キャッシュキーは次を含む。

- 描画仕様バージョン
- スタイル
- 5度角度
- 長さ
- 石造部の全幅
- 路面幅
- アーチ配置
- 詳細度
- パレット
- 模様シード

画面位置と橋IDは、模様シードへ使わない限りキーに含めない。配置時はキャッシュ済み命令を平行移動する。

キャッシュは最大128件のLRUとする。上限を超えたときは最終使用時刻が最も古い項目を破棄する。キャッシュの有無で描画結果を変えない。

## エラーとフォールバック

純粋エンジンの厳格APIは不正入力を構造化された検証エラーとして返す。テストでは不正入力を見逃さないため、厳格APIを使う。

研究ページと将来の地図アダプターは安全APIを使う。安全APIは次の場合に石造装飾を省略した平坦な橋を返し、ページ全体を停止させない。

- 最小長を満たさない
- 欄干と路面を収められない
- 非整数または有限でない寸法
- 未知のスタイル

フォールバック理由は`diagnostics`へ記録する。画面外の描画命令は配置時に切り捨て、例外にしない。フォールバックも同じ入力に対して決定論的である。

## 単体研究ページ

既存の`variants/map-08-bridge-study.html`へ橋単体の研究モードを追加する。新しい部品レンダラーはこのモードだけで使い、既存の地図描画経路へ接続しない。

研究モードは次を表示する。

- 標準サイズの36方向一覧
- 短い、標準、長い橋
- 細い、標準、太い橋
- 角度、長さ、石造部幅、路面幅を変更する操作欄
- 通常表示
- 部品境界表示
- 描画順と診断値
- 参照画像との並列比較

サイズプリセットは次に固定する。サイズ一覧は、選択中の角度を共用して9通りを同時表示する。初期角度は参照画像と比較しやすい45度とする。

| プリセット | `length` | `masonryWidth` | `roadWidth` |
| --- | ---: | ---: | ---: |
| 短い・細い | 36 | 16 | 8 |
| 短い・標準 | 36 | 22 | 14 |
| 短い・太い | 36 | 30 | 20 |
| 標準・細い | 52 | 16 | 8 |
| 標準・標準 | 52 | 22 | 14 |
| 標準・太い | 52 | 30 | 20 |
| 長い・細い | 76 | 16 | 8 |
| 長い・標準 | 76 | 22 | 14 |
| 長い・太い | 76 | 30 | 20 |

研究モードは`render=bridge-components`で選択する。角度と寸法は`angle`、`length`、`width`、`roadWidth`、診断表示は`debug`クエリへ保存し、URLだけで画面状態を再現できるようにする。地図タイル、MVT橋判定、地図上の橋配置を起動しない。既存の地図研究モードは比較用として維持するが、新しい部品レンダラーを接続しない。

## 既存12方向素材の扱い

`assets/bridge-study/directional/`の12方向PNGは、移行中の固定された視覚基準として残してよい。ただし次の制約を付ける。

- 実行時コードは読み込まない。
- 新しい部品レンダラーから再生成しない。
- 12枚の存在や内容一致を新しいテスト契約にしない。
- 新しい方向またはサイズの個別PNGを追加しない。
- 新レンダラーの視覚承認後に削除可否を別途判断する。

新しい生成ツールが保存する画像は、36方向をまとめた1枚の比較シートだけとする。

## 検証

### 自動検証

次をテストする。

1. 0度から175度まで5度刻みの36方向を生成できる。
2. 角度正規化、2.5度境界、0度と180度の対称性が正しい。
3. 長さ、全幅、路面幅の契約を検証する。
4. アーチ数、径間幅、橋脚位置が中心対称になる。
5. 斜線、欄干、側壁、輪郭に1ピクセルの穴がない。
6. 高さと壁深さが全方向で画面垂直になる。
7. 固定パレット以外の色と半透明画素を使わない。
8. 同じモデル、スタイル、シードから同じ描画命令と画素列を得る。
9. 詳細度の省略順が構造部品を消さない。
10. キャッシュキー、再利用、128件上限、LRU破棄が正しい。
11. 不正寸法と未知スタイルが安全な平坦橋へフォールバックする。
12. 実行時コードが方向別完成PNGへ依存しない。
13. 比較シート生成が個別PNGを出力しない。

旧テストのうち、12方向PNG、15度刻み、固定96×96モデルを契約にしているものは新しい部品契約へ置き換える。既存のピクセルラスタ、PNGエンコード、共有橋分類の無関係なテストは維持する。

### 視覚検証

研究ページで次を確認する。

- 標準サイズの36方向すべて
- 45度で、短い、標準、長い × 細い、標準、太いの9サイズ
- 崩れやすい5度、45度、85度、90度、135度、175度
- 参照画像に近い方向の並列比較
- 部品境界表示での隙間、重複、誤った輪郭
- 通常表示での輪郭、立体感、石積み密度
- 極小寸法のフォールバック表示

36方向一覧は標準・標準サイズで確認する。9サイズ一覧は45度で確認する。さらに5度、85度、90度、175度では短い・細いと長い・太いの両極端を確認し、標準方向だけで成立する実装を防ぐ。

視覚修正後は実画面のスクリーンショットを取得し、元の問題である「参照画像と全く違う」と「角度・大きさ変更で立体感が崩れる」を渡して独立レビューを行う。不合格なら共通部品モデルを修正し、再撮影、再レビューする。角度別の局所修正は行わない。

## 完成条件

次をすべて満たしたとき、地図配置前の部品レンダラーを完成とする。

1. 全36方向と代表9サイズが同じ石造アーチ橋に見える。
2. 欄干、側壁、アーチ、橋脚、輪郭に途切れがない。
3. 角度を変えても照明方向、高さ、壁深さが画面に対して変化しない。
4. 小さい橋で細部がノイズ化しない。
5. 大きい橋で模様が引き伸ばしに見えない。
6. 参照画像の太い石造感、二重の欄干、暗いアーチ開口を維持する。
7. 方向別完成画像を実行時に読み込まない。
8. 自動テストが合格し、最新スクリーンショットが独立視覚レビューを通過する。
9. 公開する場合はGitHub Pages上の橋単体研究モードで同じ状態を再確認する。
