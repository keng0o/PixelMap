# 彩色地図の拡大・縮小

2026-09-06 JST。依頼「mapを拡大・縮小できるようにして」への対応。style IDは `illustrated-landscape-hand-drawn-v8`。

## 対象と操作

**testのみ**。standaloneの明示的な `profile=illustrated-landscape&presentation=art` から開く専用ページと架空の構成見本。本番1・2・4マップ、通常standalone、旧topdown、素材ラボ、mobileは変更していない。

- 初期表示を基準に0.5〜4倍。実地理の基準scaleは1.05、架空の見本は画面に合わせた初期scaleを基準とする。
- スマホは2本指のピンチ、PCはホイール、共通で右下の＋／−ボタン。地図にキーボードフォーカスがある場合は＋／−キーも使える。ボタンは1段階あたり√2倍で、限界では無効になる。操作領域は44×44 CSS px。
- ホイールではカーソル下、ピンチでは2本の指の中点にある地理位置を保持する。指の中点が移動すれば同時にパンする。片指を離した時点で基準を更新し、そのまま片指で地図を動かせる。
- 操作中は直前の描画をCSS変換して追従する。ピンチ終了時、ホイールが180ms止まった時、ボタン操作後120msで地形と筆跡を再描画し、必要なタイルを読み込む。
- 古いカメラで開始した取得結果は世代番号で無視する。取得中のクリックや次のズームも扱い、全タイルが失敗した場合は最後に読めた地図と倍率へ戻す。再試行できる。
- 現在地への移動、画面サイズ変更では選択した倍率を保つ。タッチ中断、pointer captureの喪失、ウィンドウのblurでも操作状態を解除する。

## 検証で修正した道路の計算

市街地を0.5倍に縮小すると、道路の帯と端部を結合するpolygon-clippingが閉じた輪郭を作れないケースを再現した。約6千万というworld座標のまま微小な交差を計算していたことによる数値誤差だった。

専用surface処理のunionを、整数の原点を引いた近距離の座標で計算し、結果を元のworld座標へ戻す方式に変更した。元の1/1024刻みの丸めは保持する。失敗した入力を道路2本と端部の計3面・59頂点に縮約し、`tests/fixtures/illustrated-zoom-junction.json` に保存。閉じた単一面になること、接続部分が面内に残ること、入力を変更しないこと、座標移動で面積が変わらないことを回帰テストで確認する。
